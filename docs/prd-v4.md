## 1. Executive Summary

Сайт технически, личностно и продуктово зрелый: 15 проектов, 24 RU-поста, editorial-редизайн главной, граф знаний, 3 темы, i18n RU/EN partial, PostHog, CI с Lighthouse-гейтами. PRD v1–v3 закрыты.

**13.09.2026 произошёл крупный редизайн главной, не задокументированный ни в одном PRD:** editorial hero (dataviz-панель + карточка избранного кейса) + bento-раскладка, при этом **удалены CapabilitiesGrid и Testimonials** — заголовочные деливераблы v1 (REQ-014) и v2/v3 (REQ-041). PRD v4 фиксирует редизайн как фазу (as-built REQs), сбрасывает пост-редизайн baseline и называет следующий рычаг.

**Ключевой вывод из данных (90д до 14.09):** ~54 уникальных визита за 90д, конверсия «визит → контакт» 5.56% (3/54), выборка ниже порога значимости (≥100 уник./90д). **Связывающее ограничение сайта сейчас — не конверсия, а трафик.** Поэтому v4:

1. документирует редизайн и его замысел (ADR-0001: замена capabilities-grid на featured project + bento);
2. закрывает гэпы (фаннел под новый hero, архивация A/B `hero_cta_variant`, продление ревью-ритуала);
3. называет следующий рычаг короткой фазой: **контент + дистрибуция** для роста трафика.

Ожидаемый эффект: конверсия и вовлечение становятся измеримыми на пост-редизайн baseline; запущен трафиковый контур (контент-кадент + дистрибуция), без которого ни одна конверсионная метрика не значима.

### 2.5 Вывод

Сайт не «сломан» — он **без трафика недотягивает до значимости**. Рычаги по ROI:

1. **Документация редизайна** (as-built + ADR-0001) — мгновенно возвращает PRD-линию к реальности.
2. **Гэп-закрытие** (фаннел, A/B-архив, ревью-ритуал) — измерение пост-редизайн baseline.
3. **Трафик** (контент + дистрибуция) — единственный рычаг, который разблокирует все остальные метрики.

## 3. Goals & Success Metrics

### Goal 10: Конверсия в контакт — пост-редизайн baseline
- **Описание:** контакт-действие (Telegram/CV/LinkedIn/GitHub) атрибутируется по источнику и странице; новый hero-CTA (`hero_cv`) включён в контактную группу.
- **Метрика:** % уник. посетителей с ≥1 контакт-событием (cv_footer, cv_download_pdf, cv_pdf_footer, github_footer, linkedin_footer, **hero_cv**).
- **Baseline:** 5.56% (3/54, 90д до 14.09). **Track-only:** выборка ниже порога, метрика мониторится, решение по ней не принимается.
- **Target:** ≥10% при ≥100 уник./90д; **абсолют:** ≥2 контакт-инициативы/мес.
- **Срок:** квартальный трек, ревью каждые 90д.
- **Метод:** PostHog funnel ($pageview → контактная группа, окно 14д) — обновление по REQ-048.

### Goal 11: Вовлечение bento (новая поверхность)
- **Описание:** посетители главной используют новую интерактивную раскладку (bento-элементы, граф).
- **Метрика:** доля сессий с ≥1 кликом по bento (`bento_stack`/`bento_graph`/`bento_notes`); доля сессий, достигших `/graph/`.
- **Baseline:** нет (редизайн вышел 13.09, данных ~2 дня). **Track-only.**
- **Target:** ≥15% сессий с ≥1 bento-кликом; `/graph/` в топ-3 переходов с главной.
- **Срок:** 90д окно с 15.09.
- **Метод:** PostHog trends по bento-событиям + funnel главная → /graph/.

### Goal 12: Трафик (следующий рычаг)
- **Описание:** рост числа уникальных визитов до уровня, на котором конверсионные метрики значимы.
- **Метрика:** уник. визиты за 90д; контент-кадент (посты/мес).
- **Baseline:** 54 уник./90д; ~2–3 поста/мес нерегулярно.
- **Target:** ≥100 уник./90д к концу фазы контента; ≥2 поста/мес стабильно.
- **Срок:** 90д окно с 15.09.
- **Метод:** PostHog trends ($pageview dau) + ручной трек контента (UZM/контент-план).

## 4. User Stories

### Story 10: Рекрутер — новое первое впечатление
**As a** рекрутер, **I want to** за 30 секунд увидеть конкретный результат (флагманский кейс) и путь к контакту, **So that I can** решить, звать ли на интервью.

**Acceptance Criteria:**
- [ ] Hero отвечает «чем кандидат отличается» за 3 секунды (tagline + featured project card)
- [ ] Primary CTA («Смотреть проекты») и CV доступны без скролла
- [ ] Featured project показывает метрики и ведёт в разбор
- [ ] Все контакт-действия попадают в фаннел (включая `hero_cv`)

**Dependencies:** REQ-043, REQ-044, REQ-048

### Story 11: Читатель — bento-навигация
**As a** data-аналитик, **I want to** бродить по главной через bento-элементы (стек, граф, заметки), **So that I can** быстро попасть в глубокий контент.

**Acceptance Criteria:**
- [ ] Bento-элементы кликабельны и трекаются (`bento_stack`/`bento_graph`/`bento_notes`)
- [ ] `/graph/` достижим с главной в 1 клик
- [ ] События видимы в PostHog (read-data-schema подтверждено)

**Dependencies:** REQ-044

### Story 12: Владелец — трафик
**As a** владелец сайта, **I want to** растить число визитов контентом и дистрибуцией, **So that I can** дотянуть до выборки, на которой конверсия значима.

**Acceptance Criteria:**
- [ ] Контент-кадент: ≥2 поста/мес по пайплайну Z-core → пост
- [ ] Дистрибуция: UTM-метки на всех исходящих публикациях (уже собираются)
- [ ] Ревью-ритуал отслеживает трафик по источникам

**Dependencies:** REQ-051, REQ-052, REQ-053

## 6. Non-Functional Requirements

### Performance
- Без регрессий после редизайна: LCP < 2.5s, INP < 200ms, CLS < 0.1 (Lighthouse CI-гейты, 5 таргетов)
- Lighthouse CI: a11y/bp/seo ≥0.95 (error), perf ≥0.85 (warn) — сохраняется
- zero-JS-by-default: новые поверхности статик, скрипты только для интерактива
- LCP-аватар eager; остальные изображения lazy с явными размерами

### Security
- Нет новых PII-поверхностей; session recording с `mask_all_inputs: true`
- Статик — нет серверного кода/БД; `.env` не коммитится

### Scalability
- Контент-коллекции build-time; рост постов (24 → 50+) не требует архитектурных изменений
- Граф пересобирается при каждом билде

### Reliability
- `make check` валидирует внутренние ссылки + дрейф метрик
- CI-гейты блокируют деплой при регрессии
